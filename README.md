# VETMO

VETMO помогает выбирать героев в Dota 2 All Pick. Поверх игры открывается прозрачный оверлей с двумя досками пиков, Radiant и Dire, по пять позиций. Под досками показаны винрейт, пикрейт, банрейт и контрпики для текущего патча.

Приложение работает на Windows. После установки ему не нужны Python и права администратора. Интерфейс на русском языке.

## Что умеет

- Лаунчер с новостями Dota 2, таблицей меты по патчам, рангам и позициям, настройками оверлея и выбором темы.
- Оверлей без рамки, всегда сверху. Прозрачность и положение сохраняются, есть режим click-through.
- Доска пиков: пять клеток на команду. Пустая клетка открывает выбор героя с поиском и фильтром по атрибутам. Заполненная клетка заменяет героя, крестик убирает пик.
- Подсказки после каждого пика. Кандидаты сортируются по мете, винрейту и контрпикам с учётом позиции и уже выбранных героев.
- Офлайн-режим. Каталог героев и последняя загруженная мета доступны без сети. Настройки и драфты хранятся локально.

## Установка

1. Откройте страницу релизов <https://github.com/Bob1kk/VETMO/releases> и скачайте `VETMO-Setup-<версия>.exe` из раздела Assets.
2. Запустите установщик. Он ставит приложение в `%LOCALAPPDATA%\Programs\VETMO` и не требует прав администратора.
3. Запустите VETMO. Python и библиотеки уже внутри. При первом запуске нужен интернет для меты и новостей, каталог героев работает офлайн.
4. Включите в Dota 2 режим borderless или windowed и нажмите «Оверлей» в лаунчере.

Установщики не подписаны код-сертификатом, поэтому Windows SmartScreen может показать предупреждение. Подробная инструкция лежит в [`docs/user-setup-guide.md`](docs/user-setup-guide.md).

## Как устроено

Приложение написано на Python, интерфейс на PySide6 и Qt 6. Код разделён на слои, зависимости идут внутрь:

```
ui → viewmodels → services → domain
                     ↓
                    data / infra
```

`ui` содержит окна, виджеты, модели представления и фоновые задачи. Здесь нет SQL и прямых HTTP-запросов. `services` реализует сценарии: мету, рекомендации, драфт, настройки, синхронизацию и компьютерное зрение. `domain` хранит модели и правила, `data` отвечает за ORM, репозитории, Alembic и SQLite, `infra` за конфигурацию, HTTP, прокси и Supabase.

Оверлей это отдельное окно Qt без рамки и без захвата фокуса. Обычно оно принимает клики. В режиме click-through щелчки проходят сквозь него в игру. Обе доски и подсказки обновляются из одного состояния драфта, поэтому замена героя сразу пересчитывает рекомендации.

Порядок ходов задан в `src/vetmo/domain/rules.py`: Radiant, Radiant, Dire, Dire, Radiant, Dire, Dire, Radiant, Radiant, Dire. Всего десять пиков, по пять на команду. Позиция героя от 1 до 5 хранится вместе с пиком.

## Данные

### Supabase

Справочные данные лежат в Supabase. Схема находится в `supabase/migrations`, стартовые герои в `supabase/seed`. Справочные таблицы: `vetmo_heroes`, `vetmo_patches`, `vetmo_meta`, `vetmo_snapshots`, `vetmo_hero_daily`, `vetmo_hero_matchups`, `vetmo_ban_stats`, `vetmo_news`. Пользовательские данные: `vetmo_profiles`, `vetmo_drafts`, `vetmo_draft_picks`. Журнал синхронизации: `vetmo_sync_runs`.

Представления `v_vetmo_meta`, `v_vetmo_matchup_highlights` и `v_vetmo_sync_status` дают готовые срезы для приложения и панели Supabase. Для всех таблиц включён Row Level Security. Ключ `anon` или `publishable` читает справочные таблицы и не может в них писать. Пользовательские настройки и драфты привязаны к анонимной сессии и доступны только её владельцу. Ключ `service_role` обходит RLS, его используют только VETMO Admin и скрипты синхронизации.

### SQLite и офлайн-режим

Локальная база `vetmo.db` и миграции Alembic в `src/vetmo/data/migrations` остаются резервным хранилищем для разработки и офлайна. Настройки оверлея и драфты дополнительно сохраняются в `%APPDATA%\VETMO\settings.json` и `drafts.json`. Если Supabase недоступен, приложение продолжает работать на локальных данных.

Миграции Supabase применяются через SQL Editor или скрипт `scripts/apply_migration.ps1`. Набор таблиц и представлений проверяет `scripts/check_supabase_schema.py`. Порядок настройки описан в [`docs/supabase-setup.md`](docs/supabase-setup.md).

## Источники данных

OpenDota даёт каталог героев, `heroStats` с винрейтом и пикрейтом, патчи и иконки. Клиент держится в лимите 60 запросов в минуту, повторяет неудачные запросы и кэширует ответы минимум на 24 часа.

STRATZ GraphQL даёт матчапы, бан-статистику и разбивку по позициям. Окно расчёта семь дней, минимальная выборка для показа 50 матчей.

Валидатор проверяет имена героев, диапазон винрейта от 0 до 100 и URL иконок. Некорректные записи уходят в карантин и не попадают в интерфейс.

Кэш снижает нагрузку на API. Новости обновляются раз в час, иконки лежат в `assets/cache`. Приложение учитывает системный прокси Windows и переменные `HTTP_PROXY` и `HTTPS_PROXY`.

Синхронизацию запускают скрипты из папки `tools/`. Им нужен файл `%APPDATA%\VETMO\secrets.env` с ключом `service_role` и токеном STRATZ. Пользовательскому приложению эти секреты не нужны.

## Команды

| Команда | Что делает |
|---|---|
| `tools\sync_opendota.py` | загружает героев, патчи и мету из OpenDota в Supabase |
| `tools\sync_stratz.py` | загружает матчапы и бан-статистику из STRATZ |
| `scripts\build_release.ps1` | запускает тесты, собирает оба exe и установщики, проверяет состав и делает smoke-запуски |
| `scripts\publish_release.ps1` | создаёт или обновляет GitHub Release и прикрепляет установщики |
| `scripts\apply_migration.ps1` | применяет SQL-миграции к проекту Supabase |
| `scripts\check_supabase_schema.py` | проверяет наличие таблиц и представлений |
| `pytest`, `ruff check`, `mypy` | тесты, линтер и проверка типов |

Проверки запускаются из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check src tests
.\.venv\Scripts\python.exe -m mypy src/vetmo
```

## Сборка и релиз

Для сборки нужны Python 3.11 или новее и [Inno Setup 6.7+](https://jrsoftware.org/isinfo.php). Полная проверка одной командой:

```powershell
py -3.12 -m uv sync
.\scripts\build_release.ps1
```

Скрипт запускает pytest, ruff и mypy, собирает `dist/VETMO.exe` и `dist/VETMO-Admin.exe`, проверяет, что в пользовательскую сборку не попали модули сопровождения и значения секретов, делает smoke-запуски, собирает оба установщика и тихо проверяет установку и удаление.

| Установщик | Для кого | Каталог |
|---|---|---|
| `VETMO-Setup-<версия>.exe` | игрок | `%LOCALAPPDATA%\Programs\VETMO` |
| `VETMO-Admin-Setup-<версия>.exe` | управляющий | `%LOCALAPPDATA%\Programs\VETMO Admin` |

Оба установщика работают без прав администратора и поддерживают тихую установку с ключом `/VERYSILENT`. `scripts/publish_release.ps1` берёт версию из `src/vetmo/__init__.py`, создаёт тег `v<версия>` и прикрепляет файлы к GitHub Release. Готовые установщики также лежат в `release/` ветки `release/public-installer`. Портативная сборка `dist/VETMO.exe` запускается без установки, но нужна в основном для проверки и разработки.

## Разработка

```powershell
py -3.12 -m uv sync
.\.venv\Scripts\python.exe src\vetmo\main.py
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check src tests
.\.venv\Scripts\python.exe -m mypy src/vetmo
```

Для чистой локальной базы примените миграции:

```powershell
.\.venv\Scripts\alembic upgrade head
```

## VETMO Admin

`VETMO-Admin.exe` это отдельное приложение для наполнения меты. Оно показывает справочные данные, запускает синхронизацию OpenDota и STRATZ, хранит историю запусков и помогает проверять подключения. В пользовательский установщик Admin не входит.

Перед запуском создайте `%APPDATA%\VETMO\secrets.env` по образцу `installer/ADMIN-SETUP.txt`. Проверить конфигурацию без графического интерфейса можно командой `VETMO-Admin.exe --self-check`.

## Структура проекта

```
src/vetmo/
├── domain/        # модели, правила драфта, рекомендации
├── data/          # ORM, репозитории, SQLite, миграции Alembic
├── services/      # мета, новости, драфт, настройки, синхронизация, CV
├── ui/            # PySide6: окна, виджеты, модели представления, темы
├── infra/         # конфигурация, логирование, HTTP, прокси, Supabase
├── admin/         # приложение сопровождения
└── main.py        # точка входа пользовательского приложения
tests/             # unit, интеграционные и admin-тесты
tools/             # скрипты синхронизации
scripts/           # сборка, публикация, миграции, проверка схемы
supabase/          # SQL-миграции и seed-данные
installer/         # сценарии Inno Setup
assets/            # кэш иконок героев
```
